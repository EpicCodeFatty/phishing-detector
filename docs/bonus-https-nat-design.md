# Bonus A: HTTPS on the load balancer, and one NAT gateway per availability zone

Two changes to `infra/app`, built together on one branch (`feature/https-nat`) and applied in one go.
Merged into `main` only after both work on AWS.

**Do not change `infra/base`. Do not run `terraform init`, `plan` or `apply`.**

### The ideas, in one line each

| Term | Meaning |
|---|---|
| TLS | The encryption under HTTPS: the browser and the server agree on keys, and everything after is unreadable to anyone in between. |
| Certificate | A file that binds a public key to a name. A browser trusts it only if a known authority signed it. |
| Self-signed | A certificate signed by its own key, not by an authority. The encryption is identical; what is missing is proof of identity, hence the browser warning. |
| ACM | AWS Certificate Manager: where a load balancer takes its certificates from. With a real domain it issues trusted ones for free. |
| TLS termination | The load balancer decrypts; behind it, traffic continues as plain HTTP inside the private network. One place holds the certificate, and the instances stay simple. |
| Redirect 80 → 443 | Port 80 stays open only to answer "use HTTPS instead" (status 301). |
| HSTS | A header telling browsers "never use HTTP for this site again". Only safe with a trusted certificate. |
| NAT per zone | Each availability zone gets its own way out to the internet, so losing one zone does not cut off the other. |

## Part 1: one NAT gateway per availability zone

### Why

Today both private route tables send internet traffic to a single NAT gateway in the first
availability zone. If that zone fails, the instance in the other zone keeps serving users through the
load balancer, but it can no longer reach S3, Secrets Manager, CloudWatch, SSM or the package
repositories. Its logs and metrics stop, nobody can connect to it, and a replacement instance cannot
boot. The service would be running on one instance, blind, unable to heal. The assignment asks for
high availability; this removes that single point of failure for about $1.10 a day while the stack
runs.

### Changes

- `nat.tf`: one `aws_eip` and one `aws_nat_gateway` per availability zone. Each private-app route
  table routes `0.0.0.0/0` to the NAT gateway **in its own zone**.
  - The base outputs give `private_app_route_table_ids` as a map keyed by zone, but
    `public_subnet_ids` as a list ordered by zone, next to `availability_zones`. Build one map for the
    public subnets with `zipmap(local.base.availability_zones, local.base.public_subnet_ids)` and use
    the zone name as the `for_each` key everywhere, so `aws_nat_gateway.main[each.key]` in the route
    is always the gateway of the same zone. Confirm the real output shapes first; if they differ,
    adapt and say so.
  - A NAT gateway must be in a **public** subnet of its zone.
- The Auto Scaling Group's `depends_on` already refers to the NAT routes; with `for_each` the
  reference still covers every route. Check it.
- `outputs.tf`: `nat_public_ip` becomes `nat_public_ips`, a map from zone to address.
- Cost: the second gateway adds about $1.10 a day plus about $0.12 for its public address, only
  while the stack runs.
- README: replace the single-NAT trade-off with the new design; update the cost table; keep one
  sentence saying what is still in one zone (the database) and why. Update the runbook's availability
  zone entry if it exists. Update any other text that says "one NAT" or "single NAT".
- BUILD_LOG: one entry. Started with a single NAT to save cost; an availability review found that the
  surviving instance could not heal in a zone failure; changed to one per zone.

## Part 2: HTTPS on the load balancer

### Why and what

The service is HTTP only, so traffic between the browser and the load balancer is unencrypted. With
no domain there is no publicly trusted certificate, so this uses a **self-signed certificate**,
generated by Terraform and imported into ACM. The browser will show a warning; the encryption itself
is real. TLS ends at the load balancer ("TLS termination"); from there to the instances the traffic
stays HTTP on 8000 inside the VPC, as it is today. The instances do not change.

### Certificate (`tls.tf`)

```hcl
resource "tls_private_key" "alb" {
  algorithm = "RSA"
  rsa_bits  = 2048
}

resource "tls_self_signed_cert" "alb" {
  private_key_pem = tls_private_key.alb.private_key_pem

  subject {
    common_name  = "phishing-detector"
    organization = "phishing-detector (self-signed, demo)"
  }
  dns_names = [aws_lb.main.dns_name]

  validity_period_hours = 24 * 30
  allowed_uses          = ["digital_signature", "key_encipherment", "server_auth"]
}

resource "aws_acm_certificate" "alb" {
  private_key      = tls_private_key.alb.private_key_pem
  certificate_body = tls_self_signed_cert.alb.cert_pem

  lifecycle { create_before_destroy = true }
}
```

- **The common name is a short fixed string, and the load balancer's DNS name goes in `dns_names`.**
  A certificate's common name is limited to 64 characters and the load balancer's generated name is
  within a few characters of that; browsers read the name from `dns_names` (the SAN list) anyway.
- **RSA 2048** rather than an elliptic-curve key: it is accepted everywhere ACM and load balancers
  are, with nothing to check. The choice has no visible effect at this scale.
- Add `hashicorp/tls` to `versions.tf`, pinned like the others. A new provider means the owner runs
  `terraform init` again and commits the lock file.
- **The private key is stored in Terraform state.** State is local and gitignored, so it never reaches
  git, but say plainly in the README that this is a demo trade-off; in production the certificate is
  issued by ACM against a real domain, and its private key never leaves AWS.
- The certificate names the load balancer's DNS name. That only removes one of the browser's
  complaints (wrong name); the "not trusted" warning remains, by nature of self-signing.
- 30-day validity: this stack is rebuilt daily, so the certificate is regenerated with it.

### Listeners (`alb.tf`)

- New HTTPS listener on 443: `ssl_policy = "ELBSecurityPolicy-TLS13-1-2-2021-06"` (TLS 1.3 and 1.2
  only), the imported certificate, default action forward to the existing target group.
- The existing HTTP listener on 80 changes its default action to a **301 redirect to HTTPS 443**.
  This is an in-place change, not a replacement.
- **A redirected POST becomes a GET.** Anything that uploads (the load script, API callers) must use
  the `https://` address directly; posting to port 80 will appear to work and upload nothing.
- The health check between the load balancer and the instances is unchanged: HTTP on 8000.
- Remove the checkov skips that existed only because the listener was HTTP; re-run checkov and update
  `docs/security-scan.md` (counts and entries).

### Security group (`security.tf`)

- `alb-sg`: add ingress 443 from `var.allowed_ingress_cidrs`, one rule per entry, like port 80. Keep 80:
  it now only serves the redirect. Update the reason on the existing checkov skip for port 80
  accordingly.

### Application (`app/web.py`)

- Behind the load balancer, Flask sees plain HTTP. Wrap the app in Werkzeug's `ProxyFix` with
  `x_for=1, x_proto=1`, so `request.scheme` is `https` and any absolute URL or redirect the app builds
  uses HTTPS. Trusting those headers is safe here because the instances accept connections only from
  the load balancer's security group; say so in a comment.
- **No `Strict-Transport-Security` header.** With a self-signed certificate, HSTS would make browsers
  refuse the site instead of letting the user click through the warning. With a real certificate,
  HSTS would be added. Say so in the README.
- Tests: with `X-Forwarded-Proto: https`, a request sees `https`; without it, `http`.

### Tools and outputs

- `outputs.tf`: `alb_url` becomes `https://…`. Add `alb_http_url` (`http://…`) for testing the redirect.
- `scripts/load.py`: add `--insecure`, which disables certificate verification for self-signed
  certificates and prints one warning line saying so. Silence the HTTP library's own per-request
  warning in that mode, or it prints once per request. Default stays verification on. Tests.
- Every `curl.exe` command in the README, the runbook and the docs that targets the ALB over HTTPS
  needs `-k` (accept the self-signed certificate). Update them.

## Testing (owner, after apply)

```powershell
$url = terraform output -raw alb_url
curl.exe -sk "$url/health"
curl.exe -s -o NUL -w "%{http_code} %{redirect_url}`n" (terraform output -raw alb_http_url)
curl.exe -skI $url
terraform output nat_public_ips
```

Expected: `/health` answers over HTTPS; plain HTTP answers `301` to the `https://` address; the
security headers are present; two NAT addresses, one per zone. In the browser: the warning, then
"Advanced → Continue", and the site works, including upload, history and the detail page.

```powershell
python ..\..\scripts\load.py --url $url --insecure --seconds 60
```

All 200, both instances.
